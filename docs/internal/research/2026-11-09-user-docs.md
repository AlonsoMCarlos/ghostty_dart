## 2. A bilingual README on pub.dev

- **[V] pub.dev reads only `README.md`.** It has
  `readmeFileNames = ['README.md']` (pub-dev
  `pkg/pub_package_reader/lib/src/file_names.dart`).
- **[V] Relative links are not simply broken.** They are resolved, with traps.
  - pub.dev rewrites relative `href`s and `src`s through pana's
    `Repository.tryResolveUrl` (pana `lib/src/repository/repository_url_resolver.dart`;
    pub-dev `models.dart`, `urlResolverFn`) **only if repository verification
    did not fail**.
  - With no resolver, a relative link's node is **removed**. A relative image
    becomes `[alt]` text (`markdown.dart`, `_rewriteUrl`). That is the case
    before pana finishes, or when verification failed.
  - Links resolve to `github.com/<repo>/blob/<branch>/<path>`, and to `raw` for
    images. The branch comes from the `repository` URL (`tree/main/...`), so
    they point to **`main`, not the released tag**, and can drift from the
    published version.
  - **Paths containing `..` are truncated** to the part after the last `..`.
    From `packages/ghostty_dart/README.md`, `../../CONTRIBUTING.md` resolves
    to `.../packages/ghostty_dart/CONTRIBUTING.md`, which is **broken**.
  - Conclusion: use **absolute GitHub URLs** for every link that leaves the
    package directory (CONTRIBUTING, SECURITY, CODE_OF_CONDUCT, benchmarks,
    root docs) and for `README.es.md` (dio does this).
  - Same-directory relative links (`LICENSE`, `example/main.dart`) work once
    the repository is verified. Prefer absolute for consistency.
- **[V] `README.es.md` is in the published archive.** pub includes all files
  except dot-files and `.pubignore`/`.gitignore` matches
  (https://dart.dev/tools/pub/publishing).
  - It does not matter: it is a few KB and pub.dev ignores it.
  - It helps offline readers in `~/.pub-cache`.
  - Do not `.pubignore` it.
  - dio ships `README-ZH.md` without a `.pubignore` (GitHub `cfug/dio/dio/`).
- **[V] Examples of bilingual or multilingual Dart packages:**
  - `dio`: `README-ZH.md`, absolute switcher link.
  - `get` (GetX): 16 README translations, including `README-es.md`, linked
    with *relative* shields-badge links. That works only because its
    repository is the package root.
  - `riverpod` docs site: 11 locales (prior research §6).
- Order inside `README.es.md`: line 1 is `<!-- source: README.md@<sha> -->`,
  which is invisible; line 2 is `[English](abs URL) | **Español**`. This
  satisfies both AGENTS.md rules, "starts with the comment" and "starts with
  the switcher", because the comment does not render.

    `https://github.com/AlonsoMCarlos/ghostty_dart/security/advisories/new`.

## 6. Translation sync check

- **[V] No standard, dependency-free tool fits.**
  - The Linux kernel's `scripts/checktransupdate.py` is commit-based: it runs
    `git log` from the translation's commit
    (https://docs.kernel.org/doc-guide/checktransupdate.html).
  - Debian's web `translation-check` records the English revision
    (https://www.debian.org/devel/website/uptodate.en.html).
  - filgoBot and the Gitea docs `check_outdated.sh` compare commits or
    timestamps.
  - Lunaria (Astro) is npm. Adopting it would add a Node toolchain and an
    unpinned supply chain.
  - None is a pinned Dart tool. **Write a small script `tool/check_translations.dart`**
    with no dependencies, using `dart:io` and `Process.run('git', …)`, plus a
    `mise run docs:translations` task.
- **Blob sha or commit sha? Recommend the blob sha** of the English file:
  `<!-- source: README.md@<blob-sha> -->`.
  - A commit sha breaks with squash and rebase merges. The sha recorded on a
    PR branch does not exist on `main` after the merge, so
    `git log <sha>..HEAD` fails with "unknown revision". Squash is allowed
    here, and release-please flows usually squash.
  - Chicken and egg: when both files change in the same PR, you cannot write
    the sha of the commit being created. You would record the *previous*
    commit, which produces false warnings.
  - The blob sha is content-addressed. Squash, rebase and cherry-pick keep it,
    as long as the final English content is the same. The author computes it
    before committing with `git hash-object README.md`; check that the clean
    filters and autocrlf match by using `git rev-parse HEAD:<path>` in CI.
  - In CI, compare the recorded blob with `git rev-parse HEAD:<path>`.
    - Equal: up to date.
    - Different: a warning. Optionally show `git diff <old-blob> <new-blob>`
      if the old blob is present. It needs `fetch-depth: 0`, and the
      equality check alone works on a shallow clone. Or list the commits
      that touched the file since the recorded blob was last current:
      walk `git log --format=%H -- <path>` and compare the blob at each
      commit.
- **Edge cases:**
  - A missing or malformed header is an error, not a warning.
  - An English file that was renamed or deleted: error.
  - An `X.es.md` without `X.md`: error.
  - Whitespace-only edits still warn. That is acceptable: bump the header.
  - CRLF on Windows: use `git hash-object --path=<path>` to apply
    `.gitattributes`. Consider `* text=auto eol=lf` for `*.md`.
  - The blob may be unknown in a shallow clone. Equality still works.
  - Several translations of one file.
  - The CoC: the Spanish body is the official text, so its header tracks
    our English CoC file only.
- **Output:** for each stale file, `::warning file=X.es.md::…`, and exit 0 so
  it stays a warning, as AGENTS.md says. Exit 1 for structural errors.
- **AGENTS.md wording:** it says `X.md@<sha>` without saying which sha.
  Specify "blob sha (`git hash-object X.md`)" in the same change.

- **[V] dartdoc topics.** `dartdoc_options.yaml` takes
  `dartdoc: categories: "<id>": {markdown: doc/<file>.md, displayName: …}`.
  Members join a category with `{@category <id>}`, and undefined categories
  are invisible (dartdoc README). pub.dev renders them in the API docs sidebar
  under **Topics**: sqlite3's `sqlite3/dartdoc_options.yaml` gives
  https://pub.dev/documentation/sqlite3/latest/topics/hook-topic.html,
  "Build hook options topic". **Recommendation:** add `doc/hook.md`, "Build
  hook options", with the full `user_defines` reference, plus perhaps
  `doc/ownership.md` for dispose and finalizers. The README links to the
  topic URL.
- **[V] Images:**
  - dart.dev says to use absolute URLs "to make the images reliably appear".
  - Relative images resolve to `raw` on the default branch only when the
    repository is verified; otherwise they become `[alt]` text.
  - External http(s) images go through pub.dev's image proxy, and
    unproxyable ones are removed (`markdown.dart`).
  - pubspec `screenshots`: up to 10, ≤4 MB each (prior research §1). They are
    not needed for `ghostty_dart`.
- **[V] Size:**
  - README content is stored truncated at **256 KiB**
    (`maxAssetContentLength = 256 * 1024`, pub-dev `app/lib/package/backend.dart`).
  - The archive limit is 100 MB gzip and 256 MB uncompressed (dart.dev
    publishing; `pub_package_reader`).
  - The pubspec must be ≤128 KiB.
  - Our README will be about 10–15 KB.
- **[V] HTML and `<details>`.** pub.dev parses with
  `ExtensionSet.gitHubWeb` and sanitizes with `sanitize_html`, whose allowlist
  (`google/dart-neats/sanitize_html/lib/src/sane_html_validator.dart`, last
  change 2026-07-07) includes:
  - `DETAILS`, `SUMMARY`, `TABLE`, `PICTURE`, `SOURCE`, `IMG`, `DIV`, `SPAN`,
    `KBD`, `SUP`, `SUB`, `FIGURE`;
  - the attributes `align`, `width` and `valign`.
  - It has **no `style`** and no scripts. Classes are limited to
    `language-*`, `markdown-alert*`, `changelog-*` and `hash-*`.
  - So **`<details>` works**, and **GitHub alerts (`> [!NOTE]`) render**,
    because the `markdown-alert` class is allowlisted. `<picture>` with
    `<source media=…>` passes the sanitizer for future light/dark banners.
    Its `media` attribute was not verified separately.
  - Use `<details>` for the long hook options and the full benchmark tables.
